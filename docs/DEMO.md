# Самостоятельная проверка Career Quest

## Подготовка

Запустить из корня репозитория `docker compose up --build -d` и открыть
http://localhost:8000. Основной сценарий не требует ключей и внешнего CSS.
Дата сценария взята из датасета: **2026-10-01**, независимо от часов компьютера.

Войти как HR: логин **hr**, пароль **hr-demo**. Этот режим позволяет открывать
любые профили и загружать проверочные данные. Для проверки прав сотрудника открыть
отдельное приватное окно: **E0028 / employee-demo**. В этой сессии доступны только
собственные данные; другой профиль и HR-экран возвращают отказ в доступе.

Для ИИ-объяснений задать `OPENAI_API_KEY` в локальном `.env` и перезапустить сервис
командой `docker compose up -d --force-recreate`. Ключ не входит в образ и репозиторий.
Без ключа остаются рекомендации, факторы, прогноз прироста и шаблонное объяснение.

На `/hr` загрузить одновременно `docs/demo/employees.json` и
`docs/demo/activity_history.csv`. Это дополнительные синтетические профили;
в движке нет ветвлений по их ID. Повторная загрузка той же истории не дублирует записи.

## Проверка за 3 минуты

1. **Цель проверки.** Проследить весь цикл: новые данные → объяснимый выбор →
   прогноз → выполнение → изменение навыка → HR-сводка. Эти профили подготовлены
   командой для воспроизводимости и не заменяют независимые профили жюри.
2. **Рекомендация.** Открыть `/employee/DEMO_TRAP`. Public Speaking имеет
   уровень 0 и три отказа/пропуска, System Design — уровень 3 при требовании 4.
   Первым идёт критичный System Design, а не численно минимальный навык.
   Проверить три фактора, описание, ближайшую дату и прогноз **88% → 94%**.
3. **ИИ.** На `/employee/E0005?lang=ru`, в карточке Architecture Review Circle,
   раскрыть объяснение и нажать «Объяснить с помощью ИИ».
   При успехе видны текст и названия реально вызванных инструментов. Основные
   факторы на карточке всегда вычислены кодом. При недоступном API остаётся
   объяснение по фактам — это штатный режим. API различает источники `template`
   и `llm-agentic`; отсутствие ключа не выдаётся за работающую модель.
   Для `DEMO_TRAP` истории по System Design нет: используется базовый текст даже
   с ключом, без предположений об опыте сотрудника. [Примеры](AI_EXAMPLES.md).
4. **Действие.** Вернуться к `DEMO_TRAP` и отметить первый шаг выполненным. Проверить System Design
   **3 → 4**, готовность **88% → 94%** и обновлённые рекомендации.
5. **Проверка новых данных.** Открыть `/employee/DEMO_HISTORY`: по оценке
   System Design был 3, но завершение EV_006 после оценки подняло его до 4.
   Готовность **100%**, лишнего обучения нет. `/employee/DEMO_UNKNOWN` честно
   сообщает, что данных справочника не хватает.
6. **HR.** Проверить разрывы, участие, отдельный список неизвестных профилей.
   «Нет доступного шага» включает сотрудников с разрывами, а не уже готовых.

## Ответы на вопросы

Автоматическая проверка этого сценария — [test_demo.py](../backend/tests/test_demo.py).
Команды тестов и получения JSON-отчёта — в [README](../README.md#воспроизвести-результат).

- **Где здесь ИИ?** Модель читает историю и альтернативы через function calling и
  формулирует объяснение. Приоритеты и изменение навыков рассчитывает проверяемый
  движок. Модель не имеет инструмента для изменения профиля или завершения курса.
- **Почему не отдаёте ранжирование модели?** Чтобы новые проверочные профили давали
  воспроизводимый результат, а ограничения доступности и приросты не зависели от
  сгенерированного текста. Качество ИИ-текста требует отдельной проверки.
- **Есть ли доказанный бизнес-эффект?** Нет: данные синтетические. Для пилота измеряли
  бы долю добровольно начатых и завершённых рекомендаций, повторные пропуски и
  закрытие критичных разрывов по сравнению с текущей рассылкой мероприятий.
- **Готово ли для реальных сотрудников?** Это демо с опубликованными учебными
  паролями. Проверки ролей и CSRF реализованы на сервере для HTML и API. Перед
  пилотом нужны отключение демодоступа, SSO, постоянное хранение, HTTPS и
  согласование передачи данных внешнему провайдеру.
- **Что значит процент?** Доля выполненных требований целевого грейда. Частичный
  прирост навыка может не изменить процент до достижения требуемого уровня.

## Перед сдачей

- Выполнить `cd backend && pytest tests -q`.
- Проверить обычный запуск без ключа и раскрытие объяснения с ключом.
- Если демо уже меняло данные, перезапуск сервиса восстановит начальный датасет;
  после этого снова загрузить два демонстрационных файла.
- Скриншоты и описание соответствуют текущему коду; ограничения указаны явно.
- В финальном коммите нет `.env`, ключей или персональных данных.
