# Сверка с ТЗ Career Quest

Проверено по оригинальному PDF кейса и README стартового датасета.
Геймификация в ТЗ опциональна; основной сценарий — обоснованный шаг развития.

| Требование | Реализация | Проверка |
|---|---|---|
| Профиль, грейд, навыки, история | Профиль с полным списком навыков и историей; целевая роль/грейд | `test_routes.py`, просмотр RU/KK/EN |
| До 3 релевантных активностей | Критичность × разрыв, доступность, история отказов, реальный прирост с учётом потолка | `test_engine.py`, проверка всех 200 профилей в `test_history.py` |
| Минимум 3 фактора | Текущий/требуемый уровень, критичность, история видны независимо от ИИ | `test_explain.py`, карточка шага |
| Обновление прогресса | Предпросмотр прироста и готовности; выполнение пересчитывает навыки | `test_demo.py`: 88% → 94% |
| Проверочные профили | Атомарная загрузка JSON/CSV, минимальный пример из ТЗ, BOM, проверка данных | `test_upload.py`, `test_demo.py` |
| HR-view | Разрывы, сотрудники с разрывами без доступного шага, участие, неизвестные профили | `test_history.py`, `/hr` |
| Приватность и роли | Подписанная сессия, сотрудник только своего ID, HR-доступ отдельно, CSRF | `test_auth.py`, браузерная проверка 403 |
| Отклик интерфейса до 2 с | Нет внешних запросов на загрузке страницы; CSS в репозитории | Браузер и HTTP-проверка локального Docker |
| ИИ до 10 с | Общий дедлайн 8 с с отменой, без автоматических повторов SDK | Тест зависшего провайдера в `test_explain.py` |
| Запуск одной командой | `docker compose up --build`; ключ необязателен | Сборка и тесты в Docker с `--network none` и пустым ключом |
| Добровольность | `mandatory` не рекомендуются и не проходят через добровольную отметку | `test_engine.py` |

## Существенные исправления

- Учтено обучение после `last_review_date`: исходный профиль содержит оценку, а не
  автоматически обновлённые после каждой активности уровни.
- Убраны рекомендации навыков, для которых `max_level` уже достигнут.
- Добавлен прогноз результатов шага, совпадающий с фактической отметкой выполнения.
- Дата сценария взята из `meta.as_of_date`, а не из системных часов.
- Повторный импорт истории не добавляет повторный прирост и не раздувает метрики.
- Готовые сотрудники и неизвестные профили отделены от тех, кому не найден шаг.
- Устранены открытый доступ к HR/API и изменение чужого профиля.
- ИИ вызывается отдельно от загрузки страницы, имеет дедлайн, кэш и ограничение
  запросов; вызовы инструментов доступны для просмотра.

## Границы результата

Финальная проверка: 38 тестов прошли в Docker без сети и с пустым API-ключом;
Ruff не обнаружил нарушений. Браузерная проверка включала RU/KK/EN, мобильную
ширину 390 px, вход через формы и запрет доступа сотрудника к чужим данным.
В локальном прогоне страница демонстрационного сотрудника открылась за 26 мс,
HR — за 352 мс; это замеры на машине разработки, не нагрузочный тест.
С ключом проверены реальные ответы ИИ на трёх языках, без ключа — шаблонный режим.

Данные и демонстрационные пароли синтетические и опубликованы для жюри.
Перед реальным пилотом нужны отключение деморежима, SSO, постоянная БД, аудит,
проверка инфраструктуры и согласование передачи данных провайдеру.
Процент готовности — метрика требований, а не обещание повышения.
Экономический эффект на реальных сотрудниках не измерен. Модель может ошибаться
в свободном тексте; вычисленные факторы и прогноз остаются источником проверки.
